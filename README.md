# SafeStep

**A haptic wearable navigation concept, prototyped as a React web app.**

SafeStep is a vibration-based wearable navigation device. Sensors survey the area around the user and turn the distance and direction of nearby objects into distinct vibration patterns on the wrist, backed by audio voice guidance.

This repository is the interactive prototype, built for an HCI (Human-Computer Interaction) course.

## How the prototype works

Building a physical bracelet up front would be costly and slow to iterate on. Instead, SafeStep uses a **low-fidelity hardware simulation**:

- A mobile-first **React** interface is loaded onto an ordinary smartphone.
- The phone acts as a stand-in for the wearable band.
- A simulated sensor backend produces fake radar readings. When it detects a fake obstacle, the app fires the phone's vibration motor through the browser's `navigator.vibrate` API and speaks a voice alert.

This makes it possible to put the interaction design in front of real users and test it without any physical hardware.

## Features

- **Haptic and voice guidance:** obstacle distance and direction are mapped to vibration patterns and spoken alerts. Both can be toggled independently.
- **Adjustable haptic intensity:** changes apply immediately, with no reconnect needed.
- **Crowd Mode by gesture:** double-tap anywhere on the screen with two fingers to toggle Crowd Mode. It works with no visual UI, so the user doesn't need to look at the screen.
- **Live battery indicator:** a CSS battery icon that scales its width and shifts between green, yellow and red based on the level reported by the backend.
- **Manual disconnect feedback:** disconnecting plays the voice message "Band disconnected" and a light haptic double-tap.
- **Emergency watchdog:** the backend sends a heartbeat, and if it stops, the app triggers the emergency disconnect protocol.

## Architecture

The logic engine is fully separated from the UI.

- **Backend (simulation engine):** a standalone module that simulates the band and its sensors. Its `connect()` method accepts an `onSensorUpdate` callback and streams live radar data through it.
- **Frontend (React):** imports the backend module and subscribes to the callback to render state and trigger vibration and speech.

React `useRef` hooks hold the current voice and haptic settings, so callbacks registered once at connection time always read up-to-date values instead of stale ones.

## Getting started

```bash
git clone https://github.com/Amarame-Emmanuel/safestep-haptic-navigation.git
cd safestep-haptic-navigation
npm install
npm run dev
```

### Testing on a phone

The dev script runs with the `--host` flag, so the server is reachable from other devices on the same network:

1. Connect your computer and phone to the same network, such as a mobile hotspot.
2. Start the dev server and note the network URL it prints.
3. Open that URL in your phone's browser.

Note that `--host` exposes the dev server to everyone on the network, so use a network you trust.

## Demo behaviour

Some behaviour is deliberately staged for presentations:

- **Heartbeat failure:** the simulated heartbeat stops after **15 seconds** on purpose, to demonstrate the emergency disconnect protocol. This is expected, not a bug.
- **Radar pacing:** the simulated sensor updates every **2500 ms** so voice alerts have a realistic, listenable rhythm.

## Known limitations

- **Sensor data is simulated.** There is no real sensor hardware, and the "obstacles" are generated by the simulation engine.
- **iOS Safari does not support `navigator.vibrate`.** On an iPhone, voice guidance and the on-screen UI work, but there will be no vibration. Use an Android device with a supported browser to feel the haptics.
- **Voice alert pacing:** a 2.5 second alert interval suits a demo but would be too slow for real obstacle warnings.
